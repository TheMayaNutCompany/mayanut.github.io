# Support

Thank you for your interest in **The MayaNut Company** website project.

This file explains where to go for help, how to report problems, and how to contact the project appropriately.

---

## General Questions

For general questions about the website, content, branding, or project direction, please contact:

📧 **info@mayanut.com**

Examples:

- questions about site content
- questions about MayaNut™ Flour
- questions about Alicastrum or *Brosimum alicastrum*
- questions about repository structure or documentation
- questions about permissions, contributions, or project scope

---

## Bug Reports and Technical Issues

If you found a bug in the website or repository, please:

1. Check whether it has already been reported
2. Open an issue if appropriate
3. Include clear steps to reproduce the problem

Helpful details include:

- page or file affected
- browser and device
- screenshots, if relevant
- expected behavior
- actual behavior

Examples of technical issues:

- broken links
- layout problems
- JavaScript errors
- accessibility issues
- mobile or tablet rendering issues
- metadata or structured data problems

---

## Security Issues

For security vulnerabilities, **do not open a public issue**.

Please report security concerns privately:

📧 **info@mayanut.com**  
**Subject:** Security Vulnerability Report

See `SECURITY.md` for full reporting guidance.

For questions related to:

- MayaNut™ branding

please contact:

📧 **info@mayanut.com**  
**Subject:** Trademark or Licensing Inquiry

## Contributions

If you want to contribute code, content, translations, fixes, or documentation improvements, please review:

- `CONTRIBUTING.md`
- `CODE_OF_CONDUCT.md`

Before submitting changes, make sure they are tested and aligned with the project’s structure and standards.

---

## What Not to Use Support For

Please do not use project support channels for:

- spam
- unrelated promotion
- unsolicited commercial outreach
- abusive or disruptive communication
- public disclosure of security issues

---

## Response Expectations

We aim to respond as reasonably and consistently as possible, but response time may vary depending on workload and the nature of the request.

For security-related reports, refer to `SECURITY.md` for response expectations.
